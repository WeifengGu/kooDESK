 # 苦桌 (kooDESK)
 
 > 专为 Windows 10 / 11 打造的轻量原生桌面图标位置锁定与跨分辨率自适应工具。
 > **核心特性**：真实图标原生坐标读写、零遮罩、分辨率/DPI严格配置、结构保持型自适应换算、托盘开机自启动。
 
 ---
 
 ## 1. 核心技术原理与优势
 
 1. **零遮罩/原生交互（满足 R4）**：
    - 本程序直接定位 Windows 桌面底层 `SysListView32` 容器，通过跨进程内存与 `LVM_*` 消息按真实像素坐标读写图标项。
    - **不创建任何可见窗口、透明叠加层或模拟图标**，完全保留原生 Windows 桌面的右键菜单、拖拽、框选与毛玻璃特效。
 
 2. **结构保持型自适应换算（满足 R2）**：
    - 启动时启用 Per-Monitor-V2 DPI 感知，始终使用物理分辨率和真实 DPI，避免 125% 下把 1920x1080 错认成 1536x864。
    - 基准 Profile 会保存物理工作区、网格原点、水平/垂直步进和图标拓扑。
    - 切换分辨率或缩放后，先映射行列结构，再在同一目标行内寻找最近空位；同一行放不下时才换行，防止图标重叠、越界或跨区域乱跳。
    - 写入时临时关闭“与网格对齐”，多轮收敛后回读验证，再恢复用户偏好，避免后写入图标把先写入图标顶走。
 
 3. **分辨率级精确锁定（满足 R3）**：
    - 用户可在 1080P、2K、4K、远程桌面（RDP）等常用分辨率下，分别单独保存该分辨率的专属精确布局。
    - 精确配置必须同时匹配 `显示器指纹 + 物理分辨率 + DPI`；禁止把 125% 的精确坐标误套到 100%/150%。
 
 4. **事件驱动 + 周期兜底的稳定期处理**：
    - 系统原生消息监听（`WM_DISPLAYCHANGE` / `WM_DPICHANGED` / `WM_SETTINGCHANGE`）加上 `SetWinEventHook` 位置钩子捕获图标拖动。钩子固定安装在拥有消息泵的 UI 线程上，其他线程的重装请求以自定义消息转投该线程执行——`WINEVENT_OUTOFCONTEXT` 只向安装钩子的线程投递回调，在线程池线程上重装会让监听静默失效。
    - 显示设置变化后使用 2.2 秒主防抖和 5.2 秒二次稳定校验，避免在 Windows 中间态过早写入；拖动过程中会等到左键释放后才核对坐标。
    - 锁定期间每 5 秒额外做一次兜底巡检（只读比较，无差异不写入），保证即使 Explorer 不投递事件，被拖走的图标最迟一个周期内也会弹回。

 ## 3. 快速上手与操作指南
 
 ### 3.1 首次运行关键设置
 1. 在桌面空白处点击 **鼠标右键 ->【查看】**；
 2. **确保取消勾选【自动排列图标】**（若开启，Windows 系统会在每次刷新时强制打乱用户自定坐标）；
3. 双击运行 `dist\kooDESK.exe`（或在根目录执行 `.\build.ps1 -RunAfterBuild`），程序将在任务栏右下角生成托盘图标。**默认以解锁态启动**（绿色开锁图标，不锁定图标位置）；需要锁定时**左键单击托盘图标**即可上锁（转为红色小锁），再单击一次则解锁。

### 3.2 一键编译构建
在根目录下使用 PowerShell 运行：
```powershell
.\build.ps1                 # 编译成品输出到 dist/
.\build.ps1 -RunTests       # 编译并运行自动化测试套件
.\build.ps1 -RunAfterBuild  # 编译并直接启动后台托盘服务
```
 
### 3.3 托盘交互与右键菜单
 - **左键单击托盘图标**：在锁定与解锁之间切换（锁定=红色小锁、解锁=绿色开锁）。右键才弹出下列功能菜单。
 - **保存当前布局**：把当前桌面坐标保存为**唯一的基准布局**，同时写入当前显示环境的精确坐标。重复点击会直接覆盖上一条，不再有历史列表与截图。
 - **恢复基准布局**：点击即把唯一的基准布局立即应用到桌面。显示环境与基准一致时按像素精确还原，不一致时自动执行结构保持型换算。尚未保存基准布局时该项置灰，并显示为“恢复基准布局（尚未保存）”。
 - **关于**：显示软件说明、作者、代码编写、邮箱、本次编译日期（取主程序 exe 的文件写入时间，无需手工维护）与源码仓库地址。
 - **开机自启动**：注册或删除当前用户启动项，无需管理员权限。
 - **退出**：安全退出常驻托盘服务。

解锁期间若检测到图标位置发生变动，再次上锁时会直接保存当前布局并锁定（不再弹窗询问）。

> 上述菜单名、悬停提示、气泡与弹窗文字均不写在业务代码里，而是集中在 `KooDesk/Resources/UIText.cs`，改文案只需动这个文件（见 FAQ 第 5 条）。

便携数据目录（位于程序同级目录）：

```text
dist\kooDESK.json
```

改名前的旧版便携配置 `layout.json`，以及更早版本写在 `%LOCALAPPDATA%\DesktopIconLock\layout.json` 的配置，都会在首次启动时被自动静默迁移为 `kooDESK.json`，不会丢失已保存的布局。

旧版留下的 `dist\history\`（多条历史Profile与全桌面截图）已没有任何读取方，程序启动时会自动删除。

 ## 5. 常见问题排查 (FAQ)
 
1. **图标移动后没有自动弹回？**
    - 请检查托盘图标是否处于“解锁”状态（绿色开锁图标）。左键单击托盘图标即可切换为“已锁定”（红色小锁）。
    - 请确保已点击过“保存当前布局”生成过基准布局；需要回到该布局时直接点击“恢复基准布局”。
 
 2. **桌面使用了第三方美化软件（如 Stardock Fences、Rainmeter）？**
    - 第三方桌面整理软件若接管了桌面容器，可能会隐藏或替换系统的 `SysListView32`。建议在原版 Windows 桌面环境中使用本工具以获得最佳原生兼容性。
 
3. **如何开机自启？**
    - 右键托盘图标，勾选 **“开机自启动”**。程序会写入当前用户启动项，无需管理员权限。

 4. **如何验收当前实现？**
    - 自动化：`build.ps1 -RunTests`（当前 18/18 全部通过）。
    - 人工验收场景、需求对照与未覆盖项：查看 `TEST_REPORT.md`（不再提供截图，历史截图产物已下线）。

 5. **如何修改菜单名 / 提示文字？**
    - 全部可见文案集中在 [KooDesk/Resources/UIText.cs](KooDesk/Resources/UIText.cs)，按 `App` / `Menu` / `Balloon` / `Dialog` / `Prompt` / `About` 分组，改完重新执行 `.\build.ps1` 即可。
    - 锁定项与基准布局项以前在初值与刷新处各写了一份，现在都引用同一个常量，不存在“改一处、点一下又变回旧文案”的问题。
    - 例外：`LockController` 的 `reason` 参数与 `Core` 层抛出的异常文案不在此表——前者被关键字匹配用于熔断判定，改字面量会静默改变行为。
